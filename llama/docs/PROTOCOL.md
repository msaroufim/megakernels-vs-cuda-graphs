# Phase 3: independent numerical validation and matched latency

The hypothesis is that a conventional multi-kernel implementation can match or beat a megakernel on batch-one BF16 Llama-3.2-1B-Instruct decode. A win on this workload does not establish that megakernels are unnecessary in general. Both the publication-era implementation and the newer public MegaKittens Llama implementation are relevant controls. No result from the old five-percent gate is treated as independent numerical validation.

## Frozen workload and numerical evidence

Use the exact archived checkpoint/tokenizer digests, Transformers4.48.3 native eager attention FP32 (TF32 disabled) and BF16 references, and the frozen four development / eight reserved prompts in reference/prompts-v1.json. Prompt length32;128 outputs means prefill produces output0 and the benchmark executes127 decode steps. Prefill is excluded and both arms receive the same native HF BF16 prefix KV state. Coordinate permutations are lossless. All arms consume the same canonical FP32 token stream for numerical comparisons; free generation is assessed separately.

FP32 is a higher-precision reference, not exact real arithmetic. Report every step's finite status, KL(FP32||arm), canonical-token NLL difference, centered logit error, top-token margin/loss, and greedy agreement. The native BF16-versus-FP32 distribution calibrates numerical sensitivity. Canonical tokens are model-generated, not corpus labels; these NLL statistics are numerical agreement evidence, not a perplexity or downstream quality benchmark.

Before reserved evaluation, freeze every candidate's full source, configuration, harness and upstream identity. Development results may guide fixes; reserved results may not guide the same candidate's acceptance rule. If a reserved result guides a new candidate, label that suite development for the new candidate and reserve fresh inputs. Never drop difficult prompts or failing megakernel outputs.

Predeclared numerical criterion: finite outputs throughout, and the upper bound of a paired prompt-bootstrap95% interval for mean KL error minus native BF16 mean KL error is <=0. Report the analogous interval for absolute canonical-token NLL error as a second required criterion, with all per-prompt/step errors retained. Both arms are assessed symmetrically. Failure to establish this strict criterion is inconclusive numerical equivalence, not proof of incorrect model behavior. There is no post-hoc tolerance enlargement. Exact greedy agreement is reported separately because small BF16 margin changes can alter trajectories.

## Execution and latency

Primary matched scope: CUDA Graph replay of all127 decode steps, including embedding lookup,16 transformer layers, final normalization/head, argmax and output token writes. Native Python-loop execution is a separate mandatory comparison. Both use KV capacity16384; capacity256 is a secondary ablation, explicitly distinguished from the authors' allocation. Shared prefix reset occurs outside timing. Required internal barrier/position resets remain inside timing. Prefill, compilation, weight packing and host validation are outside timing; report preparation cost and extra memory separately.

Validate the actual replay after capture, every warmup and every measured execution. Archive every output token and final logits; compare them with the same arm's eager execution as reproducibility diagnostics. Bitwise or greedy nondeterminism alone is not a mathematical correctness failure. Independently HF-replay each distinct realized output trajectory, comparing actual final logits against FP32 and native BF16 on that same history, with the same predeclared KL/absolute-NLL criterion aggregated by prompt. Independently teacher-force all127 steps against the stored HF tensors in eager execution and three untimed instrumented graph replays. Graph output copies alter execution and are explicitly separate from timing; they do not substitute for inspecting actual timed outputs. Both eager and graph numerical comparisons must satisfy the numerical criterion; all nonfinite or failed numerical receipts are retained without an accepted win. Symmetric host validation happens only after the end event synchronizes. Do not use timing from uninspected graph outputs.

Realized-output numerical aggregation is separated into initial post-capture (or native-repeat), warmup, and timed stages. For each arm and stage, average observations within each process, average processes within each prompt, then apply the same paired prompt-bootstrap KL and absolute-NLL criteria. Both metrics must pass for every stage and both arms; finite and boundary checks cover every observation. Byte-identical receipt copies do not create replicates, and distinct process UUIDs are required to establish the three-process minimum. Validation reports join immutable matched receipts by SHA256.

Use a separate physical GPU per worker and isolated compiler caches. Final candidate and controls run serially on the same GPU. Record GPU UUID, runtime/source identities, and clocks/power/temperature at run boundaries. Five warmup sequences and ten measured sequences per arm replicate the authors' sample count; balanced randomized AB/BA order uses predeclared per-process seeds. At least three fresh processes per prompt/configuration; samples within a process are not independent replicates. No unrelated GPU process may overlap a measured lane.

Report all raw samples and process means. Aggregate paired log-latency ratios first within process, then across process and prompt, and use hierarchical bootstrap resampling of prompts then processes. A speed win requires the95% interval to exclude parity in the faster direction plus both arms satisfying the declared numerical/execution criteria. Cross-GPU observations are replication, not a substitute for a same-GPU pairing. Negative and ambiguous results remain in the report. No claim of reproducing exact historical vLLM/SGLang launch settings is made without recovered version/flag evidence.

## Pre-reserved implementation clarification

Before any reserved candidate outcome, development identified a large generic argmax cost. The final matched harness may use the same validated two-stage selector and fused next-token embedding for both arms. This preserves all logits, the first-index tie/NaN semantics, and the original embedding weights. It changes implementation overhead inside the same timed scope; it does not remove model work. Earlier generic-selector results remain separate by harness and helper source hashes.

BF16 model weights and intermediate stored activations remain fixed. A candidate may store the head's FP32 accumulation directly as FP32 logits, rather than applying the previous final BF16 rounding. Output dtype/shape/strides are recorded explicitly, and untimed graph validation preserves FP32 output. The released megakernel's output precision remains unchanged. This precision difference is disclosed and tested through the same independent FP32/BF16 numerical criteria; no claim of bitwise arithmetic equivalence is implied. All canonical and realized-output criteria above remain unchanged.

The final freeze binds the candidate tree, entrypoint and helper sources, protocol, prompt suite, model hashes and upstream source manifest. Reserved primary measurements require KV capacity16384,5warmups and10samples. Output-layout metadata is collected in untimed validation rather than inside native timed calls. Native and graph execution remain separately grouped, as do output precision and sequence helper identity.

Final campaign coverage and seeds are specified in CAMPAIGN.json before reserved outcomes. Each primary graph control uses all eight reserved prompts and three fresh processes per prompt. The mandatory native diagnostic uses the first listed reserved prompt and three fresh processes for each control; it is explicitly outside the full-suite primary acceptance. Both controls and all negative outcomes are reported.
